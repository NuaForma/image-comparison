# NuaForma modifications

This fork starts at upstream v4.4.0 (`188adc076324ed481300f72af627d13f5bb92ee1`). The original LICENSE is unchanged. The initial maintenance baseline preserved comparison algorithms; later behavior fixes are identified below. All production and test Java files have been relocated from `com.github.romankh3.image.comparison` to `dev.nuaforma.image.comparison`, with package/import edits and prominent modification notices.

Changes for the unreleased maintenance baseline (2026-10-25):

- `pom.xml`: independent project metadata, Java 17 API/bytecode compilation, Java 17 test compilation, pinned build/test tooling, deterministic archive timestamps and bundled attribution.
- `README.md`, `CONTRIBUTING.md`, `.github/pull_request_template.md`: independent fork identity, build instructions and contribution/review process.
- `.github/ISSUE_TEMPLATE/*.md`: remove automatic assignment to the upstream author.
- `CODE_OF_CONDUCT.md`: route fork incidents to fork maintainers instead of the upstream author.
- `.gitignore`: ignore local agent settings and generated output.
- `src/test/java/dev/nuaforma/image/comparison/ImageComparisonUnitTest.java` and `ImageComparisonUtilUnitTest.java`: identify modified tests and use Maven output paths. The save-failure test uses a real invalid parent path rather than relying on obsolete mocking behavior.
- Retired the duplicate Gradle build/launcher/wrapper, Travis workflow, old Gradle GitHub workflow and upstream funding configuration. They are recoverable in upstream history; obsolete publishing/service integrations are not used by this fork.
- Added Maven wrapper, CI, consumer/bytecode verification, maintenance/security/license review guides, changelog, agent entry point and this attribution record.

The initial maintenance baseline changed no comparison algorithms or test image fixtures. The Java package relocation changes fully qualified API names and the automatic module name; Java 17 is the new minimum. Both are intentional compatibility breaks. New repository files are NuaForma maintenance additions unless they carry an Apache wrapper header. Future changes must update this record and mark modified upstream files clearly.

Dependency/POM review (issue #14): replace the remaining mocked filesystem failure with a real temporary parent-file failure in `ImageComparisonUtilUnitTest.java`; remove Mockito and its mock-maker resource; replace the broad JUnit aggregate with explicit test-scoped Jupiter API/engine dependencies. Constrain JUnit's transitive JSpecify annotations to the reviewed 1.0.1 patch. Clarify the POM resource root and retain pinned lifecycle/artifact plugins. Production code, public API and algorithm behavior are unchanged by this cleanup.

Origin correctness (issue #3): modify `ImageComparison.mergeRectangles` to identify merged-away regions with invalid default bounds instead of a valid zero-size origin rectangle. Add synthetic corner/edge/overlap and pixel-output regressions plus a packaged-consumer origin check. This intentionally fixes false MATCH results at (0,0); public signatures, tolerance/percentage policies and existing image fixtures are unchanged.

Sequential reuse (issue #4): reset region counters at the start of `ImageComparison.populateRectangles`, shared by comparisons and mask creation. Add regressions for repeated/interleaved operations, updated options and image pixels, and stable size mismatches; extend the packaged consumer. This fixes state leakage between operations without adding a shared-instance thread-safety guarantee or changing comparison policies.

Kotlin DSL and build migration (issue #17): move the Java source/test/fixture tree into `image-comparison/` without changing production source bytes or image fixtures. Update filesystem test paths for Gradle. Replace the Maven build/wrapper with a checksum-verified Gradle wrapper and two Kotlin DSL modules. Add the optional `image-comparison-kotlin` API, tests, static HTML/KDoc reference, independent single-dependency consumer, generated publication metadata and dependency/archive verification. Update build/maintenance/security documentation and CI. Only the Kotlin adapter requires Kotlin; Java core APIs and runtime dependency boundary are unchanged. Gradle wrapper code retains its Apache headers; no artifact or documentation is externally published.

Approved comparison contracts (issues #6/#7/#8) and bounded-stack grouping (#9): change `ImageComparison` to measure non-excluded differing pixels, retain accepted-match percentages, treat unequal dimensions as 100% without resizing, compare alpha alongside unchanged RGB normalization, and apply rectangle area/count limits only when drawing. Replace recursive traversal with a heap worklist preserving the existing directional rays/threshold semantics. Update the exact ARGB convenience metric in `ImageComparisonUtil` while preserving the legacy raw `pixelDiff` helper. Add an overload to `ImageComparisonResult.defaultMatchResult` for measured percentages, retaining the existing signature. Document intentional behavior changes in the contract/README/KDoc/HTML/changelog and update Kotlin diagnostic terminology. Add synthetic Java/Kotlin regressions and packaged constrained grouping measurements; update two historical percentage assertions and isolate the RGB-only reuse test with equal alpha for the approved semantics without changing or regenerating any image fixture. No new runtime dependency or publication is introduced.

Image input, resources and result collections (issues #11/#12/#13): validate ImageIO's nullable decode result for filesystem and classpath paths, preserve existing lookup order/file decoding and exception types, sanitize diagnostic control characters and retain I/O causes. Close library-owned classpath streams with try-with-resources; route comparison rendering and image conversion through a shared exception-safe graphics ownership helper, including setup failures. Initialize per-result rectangle lists and normalize null setter input to a new list without changing non-null list aliasing/mutability. Update Kotlin diagnostics to use the non-null collection contract. Add public input/factory/ownership regressions, instrument real streams and Graphics2D delegates through package-private seams without a new public API or dependency, and extend standalone Java/Kotlin consumers and documentation. Existing image fixtures, drawing pixels, comparison policies and dependency versions remain unchanged.
